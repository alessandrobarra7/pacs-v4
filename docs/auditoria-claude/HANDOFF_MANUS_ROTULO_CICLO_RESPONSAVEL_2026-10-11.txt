================================================================================
2. CAUSA RAIZ
================================================================================

Arquivo: client/src/pages/finance/FinanceMeuResponsavel.tsx

A tela usa um estado local (year, month) para a navegação entre períodos, com
referenceDate sempre fixado no dia 15 do mês selecionado:

    const referenceDate = new Date(year, month - 1, 15).toISOString();

Esse referenceDate é enviado ao backend (myResponsavelSummary), que calcula
CORRETAMENTE o ciclo de cada unidade via calculateFinancialCycleDates(start_day,
end_day, referenceDate) — a mesma função usada em todo o resto do sistema — e já
devolve um campo cycle_label pronto e correto por unidade.

O bug: o componente de card por unidade, em vez de usar esse u.cycle_label vindo do
backend, RECALCULAVA seu próprio rótulo localmente, com uma IIFE que assumia que o
mês selecionado (month/year do estado da tela) é sempre o mês de INÍCIO do ciclo:

    // comportamento antigo (removido):
    // `${pad(sd)}/${pad(month)} – ${pad(ed)}/${pad(month)}`  (ciclo no mesmo mês)
    // `${pad(sd)}/${pad(month)} – ${pad(ed)}/${pad(nextM)}`  (ciclo cruza o mês)

Essa suposição é falsa para ciclos que cruzam o mês (start_day > end_day, ex:
start_day=24, end_day=23). calculateFinancialCycleDates decide o mês de início real
comparando o DIA do referenceDate (fixo em 15) com start_day:
  - se 15 >= start_day: o ciclo é [mês_selecionado.start_day, mês_seguinte.end_day)
  - se 15 <  start_day: o ciclo é [mês_anterior.start_day, mês_selecionado.end_day)

No segundo caso, o ciclo real COMEÇA NO MÊS ANTERIOR ao selecionado — mas o código
antigo do frontend sempre montava a string assumindo que o início é no mês
selecionado, produzindo um rótulo de data incorreto (deslocado em um mês) sempre que
esse segundo ramo se aplicava.

Importante: isso é um bug de EXIBIÇÃO DE TEXTO apenas. Os números (total_laudos,
valores a pagar) vêm de outro campo do mesmo payload, calculados corretamente pelo
backend com o mesmo referenceDate — não foram afetados.
